# Sendspin Bridge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the NAD C368 BluOS card a Music Assistant Sendspin player, in sync with other Sendspin players, through the existing `sovi-airplay` plugin.

**Architecture:** A new C++20 program `sendspin-bridge` wraps `sendspin-cpp` (player, metadata, artwork, controller roles) and writes RTP straight to dspout's unix socket, using dspout's clock (forwarded by the Perl plugin) as its audio sink timeline. The Perl plugin `sovi-airplay` stays the only BluOS-protocol speaker; it runs the bridge as a second child next to shairport-sync, talks to it in JSON lines over stdin/stdout, writes the avahi service file, and arbitrates AirPlay vs Sendspin (newest sender wins).

**Tech Stack:** C++20, CMake ≥ 3.16, `sendspin-cpp` v0.10.0 via FetchContent (ArduinoJson 7.4.1 is a PUBLIC dependency of its `sendspin` target and is reused for the plugin protocol), GoogleTest 1.15.2 for native tests, Perl 5.14 core modules (Test::More for tests), Docker `debian:bookworm-slim` armv7 for the static cross-build.

**Spec:** `docs/superpowers/specs/2026-11-20-sendspin-design.md`

## Global Constraints

- Card: ARMv7-A Cortex-A8, glibc 2.30, perl 5.14 (JSON::PP available), no compiler; only `/var/data` persists; `/tmp` is tmpfs.
- The cross-built bridge is fully `-static` (bookworm glibc 2.36 > card 2.30), flags `-march=armv7-a -mfpu=neon -mfloat-abi=hard -O2`, stripped, output `build/out/sendspin-bridge-armv7`.
- `sendspin-cpp` pinned to `v0.10.0`. Roles player/metadata/artwork/controller ON; color/visualizer/source OFF; `SENDSPIN_ENABLE_OPUS=OFF`.
- The bridge must also build and run its tests natively on macOS (Apple clang 21) and Linux.
- RTP to dspout: `/var/data/pcm_rtp_socket01`, 20-byte header per `docs/PROTOCOL.md` §4 (`0x80, 0xe0, seq u16 LE, ts u32 LE µs, rate/50 u16 LE, frames u16 LE, bits u8, 0, channels u16 LE, 0 u32`), S16LE stereo, 363 frames per packet, timestamps continuous, never stamped in the past.
- Constants: LEAD 250 000 µs, LEAD_MAX 400 000 µs, slew ≤ 1000 ppm, step log threshold 5000 µs, stream-end grace 3 s (same as `$GAP_S`), child restart after 3 s, `required_lead_time_ms` default 1000, artwork JPEG 600×600 `max_image_bytes` 262 144, formats offered FLAC 2/44100/16 then PCM 2/44100/16, server port 8928, TXT `path=/sendspin`.
- Perl stays the only BluOS-protocol implementation. The bridge never opens `airplay_req01`/`airplay_cmd01`.
- Never touch `dspout`, `sovi-core`, or anything watchdog-protected; no new rootfs edits; never run `/sbin/reboot` on the card.
- Settings dir on the card: `/var/data/airplay/sendspin/` with `disabled`, `lead_ms`, `delay_us`, `no_unpaired`, `debug`, `pairing-token` (0600), `state.json` (0600).
- Avahi file `/var/avahi/services/sendspin.service`: `<name>` = player name, `<type>_sendspin._tcp</type>`, `<port>8928</port>`, `<txt-record>path=/sendspin</txt-record>`, `<txt-record>name=<name></txt-record>`.
- Library callbacks: `on_audio_output` runs on the sync thread; every other callback on the thread that calls `client.loop()`. `notify_audio_played` is thread-safe. `loop()` must never be called from a callback. Every frame a write accepts counts as queued until reported, so frames the sink discards must be reported as played at the moment they are discarded (integration guide; this refines design rule 5, which said "no report").
- Commit after every task with a message ending in `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

Inputs the spec implies but doesn't spell out, most likely to bite first:

1. **A write arrives in a format other than 2 ch / 44100 / 16** (MA ignores the offer or a future stream/start changes format). Expected: the sink discards it, reports it played, logs once per format change, never writes a mis-labelled RTP packet. Test in Task 3.
2. **The dspout socket send fails** (socket missing after a dspout restart, EAGAIN). Expected: the write still returns all bytes, the timeline keeps advancing, the error is logged at most once per 5 s, and the bridge keeps running. Test in Task 3.
3. **The plugin dies or closes stdin.** Expected: the bridge sees EOF and exits within one loop tick so port 8928 is free for the restarted plugin's bridge. Test in Task 2 (reader) and Task 6 (loop exit).
4. **The player name contains `&`, `<` or quotes.** Expected: the avahi XML is escaped and still parses. Test in Task 9.
5. **An `N` clock report arrives while AirPlay owns the stream, or before the Sendspin stream is live.** Expected: Perl forwards `clock` to the bridge only while the Sendspin front end owns a live stream. Test in Task 10.

The bridge's main loop thread is the "main loop" in the sendspin sense. `RtpSink` is the only object touched from two threads (sync thread `write()`, main loop `set_live()`/`on_clock()`) and guards itself with one mutex.

**Files:**

**Interfaces:**
- Produces (namespace `bridge`):
  ```cpp
  class DgramSender { public: virtual ~DgramSender() = default; virtual bool send(std::span<const uint8_t> packet) = 0; };
  class UnixDgramSender : public DgramSender { public: explicit UnixDgramSender(std::string path); bool send(std::span<const uint8_t>) override; };  // unconnected SOCK_DGRAM, sendto(MSG_DONTWAIT)
  struct SinkClocks { std::function<int64_t()> mono_us; std::function<int64_t()> real_us; std::function<void(int64_t)> sleep_us; std::function<void(std::string_view)> log; };
  struct SinkOptions { uint32_t rate{44100}; uint8_t channels{2}; uint8_t bits{16}; uint16_t frames_per_packet{363};
                       int64_t lead_us{250000}; int64_t lead_max_us{400000}; int64_t max_slew_ppm{1000}; int64_t step_log_us{5000}; };
  struct WriteResult { size_t bytes; uint32_t frames; int64_t finish_mono_us; bool discarded; };
  class RtpSink {
   public:
    RtpSink(DgramSender& out, SinkClocks clocks, SinkOptions opts);
    static std::array<uint8_t, 20> pack_header(uint16_t seq, uint32_t ts_us, uint32_t rate, uint16_t frames, uint8_t bits, uint16_t channels);
    void set_live(bool live);                           // main loop; false drops the timeline and any buffered partial packet
    void on_clock(int64_t pos_us, int64_t real_us);     // main loop (Task 4)
    WriteResult write(std::span<const uint8_t> pcm, const sendspin::AudioFormat& fmt, uint32_t timeout_ms);  // sync thread
    bool live() const;
    std::optional<int64_t> current_pos_us() const;      // dspout position now, from the mapping; nullopt without a clock
    std::optional<int64_t> mono_of_ts(int64_t ts_us) const;
  };
  ```
- Semantics fixed here: `write` returns `bytes == pcm.size()` always except the timeout case in Task 5. Discard path (not live, or live without a clock yet, or `fmt` ≠ configured format): no packets, `frames = pcm.size() / bytes_per_frame`, `finish_mono_us = mono_us()`, `discarded = true`. Live path: whole 363-frame packets are sent; leftover frames are buffered for the next write; `finish_mono_us = mono_of_ts(ts_of_next_packet_start + buffered_frames × 1e6/rate)`. `ts` is kept as a double in µs and truncated for the header. Stale timeline (next packet's `ts` < `current_pos_us()`) → log `re-anchor` and set `ts = current_pos_us() + lead_us`. First packet after `set_live(true)` → log `anchor`, same formula. A failed `send` is logged at most once per 5 s of mono time; the timeline still advances.

- Consumes/produces: `RtpSink::on_clock`, `mono_of_ts`, `current_pos_us` from Task 3, now with slew. Internal model (the implementer's; stated so the tests are unambiguous): the mapping is an `offset = pos_us − real_us` (stream position at CLOCK_REALTIME zero). `applied_offset` moves toward `target_offset` by at most `max_slew_ppm × elapsed_real_us / 1e6` per query, where elapsed is since the last query/update.
